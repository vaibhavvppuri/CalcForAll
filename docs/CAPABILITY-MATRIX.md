## What the saved conversations establish

The original product thesis is a phone calculator for everyday and scientific work, with exact answers, graphing and Indian numbering/units. The historical v1 specification lists 53 features after the entry-correction and undo amendments. The old heading saying “51” is stale. Later design and decision documents refine how entry, references, error states and formatting must behave.

The filenames and chat titles “Calculator App v2”, “v3”, and “v4” also name conversation continuations. They do not prove that corresponding software releases exist. An original saved coding conversation ended at **M7-2 Stage A**, the themed Android scaffold, and its receipted commit was the repository's starting commit `40fff97`. Graph/history/settings and a real 2D renderer were explicitly later work at that checkpoint. The supplied browser-assets ZIP contains saved-page assets, not another calculator implementation.

The browser-saved chats include collapsed/“load later” sections. Only their available text and the actual local repository can be assessed; missing original messages and linked artifacts have not been reconstructed. Historical instructions to stop, preserve a precise old test count, or avoid later features are reference context. The current user's authorization expands the work and governs this build.

The historical software roadmap places handwriting, full CAS and calculus in v2; photo solving, 3D plots/sliders/animation and currency in v3; and a public API in v4. The current offline/free/no-upload requirement changes that roadmap: local OCR and a loopback API fit; cloud solving and live exchange-rate fetching do not. A bounded CAS subset and a symbol pad must not be called full CAS or general handwriting recognition. Delivering an API does not, by itself, complete the preceding version gates.

## Acceptance sequence

1. **Correctness and build:** all current core/API/Android tests complete, errors are investigated, and required boundary checks pass. Test counts come from fresh XML after completed builds. Battery PROBE cases remain observations, not passing assertions.
2. **Essential app workflow:** install the actual APK; enter ordinary/scientific expressions, solve an equation, convert a unit, use a matrix/statistics tool, graph/trace, edit linked history, change settings, rotate and restart. Confirm values against known examples and confirm errors clear a stale displayed answer.
3. **Offline and recovery:** inspect the merged manifest; run calculations and first-use OCR without network; verify saved state after process restart and explicit data deletion; preserve an unreadable saved file instead of silently overwriting it.
4. **Input and accessibility:** test typing, paste, structured edits, flicks and long-press delete; review large-font/small-screen behavior and screen-reader labels. Recognition requires correction and explicit user acceptance.
5. **Reproducible handoff:** provide source, build/run instructions, debug/installable APK, licenses/notices, local API package, screenshots, current test receipts and known limitations. A debug APK/source handoff is not a Play Store release.

An API 23 manifest is a compatibility target, not a proof of every Android version/device. Record the actual tested API/device separately. Store signing, store listing, applicable target-SDK policy, privacy hosting and Play review are additional publication work; no store submission or public deployment is authorized by merely preparing files for the user's GitHub upload.

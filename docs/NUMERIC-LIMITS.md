# Numeric work and allocation budgets

CalcForAll keeps rational arithmetic exact and irrational arithmetic in BigDecimal. It deliberately refuses calculations that exceed a fixed work or allocation budget. Refusal is an ordinary typed error, not infinity, a fabricated zero, or a device-dependent timeout.

| Boundary | Budget |
| --- | --- |
| Expression input | 65,536 characters in the core; app/API may be stricter |
| Individual literal | 10,000 digits; decimal scale between −20,000 and 20,000 |
| Rational numerator and denominator | 131,072 bits each after reduction |
| Rational addition/comparison scratch values | At most 262,145 bits |
| Session compute precision | 5–50 digits, at least four more than display precision |
| Direct numeric kernel precision | Up to 1,024 digits plus bounded internal guard digits |
| Decimal value | Adjusted exponent within ±32,768, scale within ±65,536 |
| Integer powers, real and complex | Absolute exponent at most 1,000,000; result size still bounded |
| Factorial | Argument at most 10,000 |
| Permutations/combinations | At most 10,000 product terms; result size still bounded |
| General transcendental input | Adjusted exponent within ±10,000 |
| Exponential and hyperbolic argument | Absolute value at most 10,000 |
| General non-symbolic trig argument | Absolute value at most 1,000,000 radians |
| Trial square-factor extraction | Divisors through 4,096, plus a whole-number perfect-square check |

Input budgets are checked before converting strings or expanding decimal scales into large integers. Rational multiplication and division cross-cancel before multiplying. Addition uses the shared denominator and cancels before constructing the final denominator. Integer multiplication checks operand bit lengths before allocation. Square roots reduce numerator and denominator separately, so a large perfect-square fraction can still have a small exact root. Exact integer root detection uses integer Newton iteration; a huge root index takes work independent of that index, using guarded `exp(log(x)/n)` when no exact root exists.

Session precision is capped at 50 digits because mixed exact/inexact arithmetic operators use a 50-significant-digit fallback context. The app and API expose at most 32 displayed significant digits; the lower-level Settings type permits up to 46 with four guard digits. Direct numeric kernel calls can request more precision within their allocation budget, but that is not an end-to-end accuracy guarantee for an arbitrary expression. Exact rational arithmetic is independent of this approximation context, subject to the allocation budgets above. Like other finite-precision arithmetic, inexact operations can lose accuracy through cancellation or when adding quantities with very different magnitudes.

The decimal addition fallback rejects a completely discarded nonzero operand. For example, `(1e80+sqrt(2))-1e80` reports a precision limitation instead of silently returning zero; `(1e80+1)-1e80` remains exactly one because it stays rational. This is a narrow guard, not a general proof against cancellation or accumulated rounding error.

Approximate zero remains approximate when added to, subtracted from, multiplied by, or divided by an ordinary nonzero value. This preserves the estimate marker when reusing an approximate tool result that happens to be zero. Exact zero remains an exact annihilator: `0*approx(2)` and `0/approx(2)` are exactly zero for the known finite nonzero stored value. Division by either kind of zero is still refused. This provenance marker is not an uncertainty interval.

Real and complex integer powers share the exponent budget. Rational powers take an exact root first when possible; half-integer powers preserve rational/surd forms. Otherwise they evaluate the bounded logarithmic product using the exponent ratio directly, avoiding an enormous `base^numerator` temporary for a moderate fraction. Negative bases retain the real odd-root convention. General real powers check the logarithmic product before calling the exponential kernel. Exact standard angles retain their symbolic reduction, including enormous exact multiples of π; a non-symbolic argument above the trig budget reports overflow instead of attempting unreliable argument reduction. Square-factor extraction may leave a larger square factor inside a radical: its value remains exact, but its written form may not be fully reduced.

These limits protect the numeric layer. They do not promise a universal wall-clock deadline for every legal expression, and callers should also bound batch sizes and AST depth. The API and app impose their own smaller input limits and run calculations away from the UI thread. Tests cover ordinary scientific notation beyond binary64 (`1e±309`), 1,800-term sums, billion-index roots, cross-cancellation of large rationals, exact combinatorics, and typed refusals at the boundaries.

Main-entry equation and system routing has an additional iterative preflight before recursive unknown discovery and polynomial extraction: at most 512 expression nodes in total across both sides of every equation, with AST depth at most 64. Exceeding either limit returns a typed unsupported error asking for a simpler expression. This also catches long left-associated sums whose AST is deep despite having few parentheses. Plain scalar evaluation retains its separate iterative long-sum path; the equation limit does not impose a new 512-node cap on direct core scalar calculations. The API independently applies its advertised 512-node/depth-64 request limit to all expressions. Graph root/intersection analysis has its own structural and work budgets described below.

The history tape holds at most 5,000 entries, 90,000 total editor nodes, 16,384 nodes per calculation, and nesting depth 128. Reaching a limit rejects the new operation explicitly; it never silently discards history. The last 100 whole transactions can be undone. Dependency analysis uses iterative strongly connected components and topological ordering, avoiding recursion and per-row transitive reachability tables. Rejected edits leave the current tape, undo/redo history, and next entry identifier unchanged. The durable session codec has a separate total limit that also includes the current editor.

Regression uses centered sums to preserve small variation in large-offset data. A constant response still gives its valid horizontal fitted line, while Pearson correlation and the coefficient of determination are explicitly undefined (`null`). Constant predictor values remain a typed domain error.

Graph root/intersection analysis accepts 2–4,096 samples and checks an iterative 512-node, 64-depth expression budget before recursive polynomial extraction. A shared `RootSearchOptions` budget covers scanning, bisection and final candidate verification: 10,000 evaluations and 5 seconds by default, with hard caps of 20,000 evaluations and 15 seconds. Its optional `shouldStop` callback and thread interruption are checked around operations. Existing calculator and root-finder calls remain valid without options. An individual bounded arithmetic/extraction call cannot be preempted halfway through its work.

An exhausted or cancelled search returns a typed unsupported failure, never partial roots labelled as a complete search. Uncomputed samples also make the search incomplete. Intersections require equal settings and equal memory bindings for both functions; the API refuses mismatched contexts rather than evaluating the second curve under the first curve's memory.

Numeric graph roots are residual-checked candidates under continuity assumptions, not exact roots or a proof that every root was found. A numeric sign bracket must shrink to width at most `1e-12`; both current endpoint residuals must decrease by a factor of at least `1e6` relative to their respective original endpoint residuals. The selected endpoint must pass both absolute residual `1e-6` and `1e-6` times the smaller original endpoint residual. Final substitution repeats that candidate-specific check. Refinement continues beyond the width threshold when residual evidence is insufficient, subject to the same time/evaluation/120-bisection limits. Tiny continuous roots, including `1e-300*sin(x-0.1234567)` and `1e-300*(x^3-2)`, remain supported.

No finite sample rule establishes continuity for an arbitrary expression. For example, `(x-0.1234567)^2/(x-0.1234567)` agrees with a line except at a removable hole at that line's only root. Likewise `(x-p)*ln(abs(x-p))` has a zero limit at an undefined point. This release explicitly refuses these numeric root searches before sampling rather than presenting a hole as a root.

The numeric analysis subset permits addition, subtraction, multiplication, division by a closed nonzero real constant, variable bases raised to fixed nonnegative integer powers, and positive closed bases raised to supported variable expressions. Supported dependent functions are `sin`, `cos`, `atan`, `abs`, `cbrt`, `exp`, `sinh`, `cosh`, `tanh`, `asinh`, `hypot`, `min`, and `max`, including their registered aliases. Constants use the curve's own settings and memory and consume the shared evaluation budget. Variable-dependent denominators/negative or fractional powers, restricted-domain functions such as `ln`, `sqrt`, `tan`, `asin`, and discontinuous operations such as floor, sign, and factorial receive an explicit unsupported-analysis explanation. Closed subexpressions can contain those functions when they evaluate successfully. Curve plotting and point tracing remain available; exact low-degree polynomial solving follows its existing path. This is a limited continuity-safe syntax subset, not a general symbolic or interval domain prover.

Physical constants were checked against the [NIST complete 2022 CODATA table](https://physics.nist.gov/cuu/Constants/Table/allascii.txt) on 10 November 2026. Electron mass is `9.1093837139e-31 kg` with standard uncertainty `2.8e-40 kg`; proton mass is `1.67262192595e-27 kg` with uncertainty `5.2e-37 kg`. The molar gas constant stores the full exact SI product `NA × k_B = 8.31446261815324 J/(mol·K)`. Measured constants remain labelled with nonzero uncertainty.

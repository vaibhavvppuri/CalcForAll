# Calculator regression batteries

This test-only module exercises the public core, tape and structured editor. It ships no application code and requires no service, credentials or external fixture download.

Run from the repository root with JDK 21 and the included Gradle 8.10.2 wrapper:

```text
./gradlew :battery:test --console=plain --max-workers=1
```

On Windows use `./gradlew.bat` instead. After Gradle and its dependencies have been cached, add `--offline`. Use the full unfiltered task for release verification. Some Kotest/Gradle combinations do not discover class-name filters correctly; an unmatched filter fails instead of silently succeeding.

The default task executes these complete case sets:

| Battery | Scope | Records | JSON output relative to this module |
| --- | --- | ---: | --- |
| B1 | Expression evaluation and display | 1,000 | `build/battery/chunk-0.json` |
| B2 | Tape, references, replay and history | 500 | `build/battery/b2-chunk-all.json` |
| B3 | Structured editor and keypad reference model | 520 | `build/battery/b3-chunk-all.json` |

Every selected case produces a record, coverage and unique IDs are checked, and any `FAIL` fails the Gradle task. Records are written before the verdict assertion so failures remain inspectable. `PROBE` means an observed case without a settled passing contract; it is never counted as `PASS`. Escaped exceptions and hangs fail even for B1 probes. The supplementary `HarnessSafetySpec` checks the probe safety gate and independently handwritten Ans insertion, selection, navigation and deletion expectations. Its six test cases are separate from the 2,020 battery records; Gradle's test count is not the battery case count.

B1's vendored fixture is `fixtures/B1-v1.6.json`, version 1.6, with SHA-256 `A129BEFE62AF74A86470FB2A4F52D06452F2F89483AE26D3C9EDCD0324A4A8DC`. Its 78 original probes are retained without relabeling. B2 and B3 cases are generated by `B2Cases` and `B3Cases`; B3 uses a separate reference editor, sharing data types but no production editing operations.

B1 records elapsed time per expression and enforces a 10-second cap. The 2-second slow marker is informational, not a performance assertion. The task always reruns its cases rather than reusing an up-to-date result.

Historical calibration, diagnostic and chunk modes remain available through `battery.chunk`; `battery.file` and `battery.out` override paths. `battery.unsupported` can downgrade required capabilities for exploratory calibration. These partial or downgraded runs are not full regression verification. The release command above leaves all overrides unset.
